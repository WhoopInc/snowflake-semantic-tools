# Snowflake Semantic Tools

SST builds Snowflake semantic views, Cortex Agents, their tools and evaluations,
Cortex Extension skills and plugins, and CoCo Desktop profiles from files in a
dbt project, and publishes them with a reviewed plan.

## Start here

- [Getting started](getting-started.md): from a dbt project to a published
  semantic view.
- [Concepts](concepts.md): artifacts, members, references, and the
  `validate` / `plan` / `apply` pipeline.
- Coming from SST 0.3? [Migrating from 0.3](guides/migrating-from-0.3.md).
- [Glossary](glossary.md): the terms these pages use, and the words that mean
  different things in Snowflake, dbt, and SST.

## A worked example

`tests/fixtures/reference_project/` in this repository is a complete project
that uses every artifact type: three semantic views, tools, three agents, an
eval, three skills, a plugin, and two Desktop profiles. The test suite validates
and compiles it on every change. Run it offline with the dbt manifest committed
beside it:

```bash
sst --project-dir tests/fixtures/reference_project \
    --manifest tests/fixtures/reference_project_manifest.json \
    validate --no-snowflake-syntax-check --no-strict
```
